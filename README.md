# Aegis Fraud AI

End-to-end fraud detection platform built on the [IEEE-CIS Fraud Detection](https://www.kaggle.com/c/ieee-fraud-detection) dataset.

The system combines classical ML models, rule-based explainability, a RAG knowledge base (lightweight local RAG prototype), a multi-agent orchestration layer, and a production-ready FastAPI.

## Setup

### 1. Clone and create virtual environment

```bash
git clone <repo-url>
cd Aegis-Fraud-AI-1
python -m venv .venv
source .venv/bin/activate  
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
pip install faiss-cpu sentence-transformers ollama
```

> Core API deps (`fastapi`, `uvicorn`, `dependency-injector`, `pyyaml`, `httpx`) are
> already listed in `requirements.txt`.

### 3. Download dataset

Download from [Kaggle IEEE-CIS Fraud Detection](https://www.kaggle.com/c/ieee-fraud-detection/data) and place CSV files in:

```
data/raw/ieee-fraud-detection/
    train_transaction.csv
    train_identity.csv
    test_transaction.csv
    test_identity.csv
```

### 4. Run the notebooks

Open Jupyter and run notebooks 01–10 in order:

```bash
jupyter lab
```

### 5. Export the scoring model (optional but recommended)

After running notebooks 01–06, export a real LightGBM artifact for `/score`:

```bash
python scripts/export_scoring_model.py
```

If interim pickles are missing, the script trains on reproducible synthetic API-signal
data so the API still loads `models/anomaly_model.joblib` instead of the heuristic.

## Running the API

### Option A — Inside Notebook 10

Open `notebooks/10_api_development.ipynb` and run all cells. The notebook imports
the modular app from `src/api/` (no duplicated logic) and starts the server at
`http://127.0.0.1:8765`.

### Option B — Standalone server

```bash
python scripts/launch_api.py
# or with custom host/port:
python scripts/launch_api.py --host 0.0.0.0 --port 8000
```

Dashboard: `http://127.0.0.1:8000/` · Swagger: `http://127.0.0.1:8000/docs`

### Architecture highlights

- **Dependency Injection:** `dependency_injector` `Container` wires singleton services
  (`ScoringService`, `ExplanationService`, `RuleService`, `RagService`). Routes use
  `@inject` + `Depends(Provide[Container....])` — thin handlers, testable services.
- **Strategy pattern:** `ScoringService` delegates to an `AnomalyModel` implementation:
  - `pipeline-lightgbm-api-signals` when `models/anomaly_model.joblib` exists
  - `signal-weight-heuristic` fallback otherwise
- **Modular layout:** schemas, services, routes and the DI container live under `src/api/`.

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Self-explanatory fraud dashboard UI |
| POST | `/score` | Compute anomaly risk score (LightGBM or heuristic fallback) |
| POST | `/explain` | Generate plain-language explanation |
| GET | `/rules/list` | Catalog of fraud rules with descriptions |
| POST | `/rules/evaluate` | Evaluate all fraud rules against feature dict |
| POST | `/rag/query` | Search the knowledge base with a free-text query |
| GET | `/health` | Server health + rules/KB/model metadata |

### Example: `/score`

```bash
curl -X POST http://127.0.0.1:8000/score \
  -H "Content-Type: application/json" \
  -d '{
    "transaction_id": "TXN-001",
    "TransactionAmt": 875.00,
    "hour": 2,
    "account_age_days": 1,
    "num_txn_last_1h": 9,
    "P_emaildomain": "protonmail.com",
    "card_type": "credit",
    "country_mismatch": 1
  }'
```

> `device_trust_score` is optional (defaults to `0.5`).

## Requirements

Core dependencies:

| Package | Purpose |
|---------|---------|
| `pandas`, `numpy` | Data processing |
| `scikit-learn` | Feature engineering, anomaly detection |
| `xgboost`, `lightgbm` | Score fusion models |
| `faiss-cpu` | Vector store for RAG |
| `sentence-transformers` | Embedding generation (optional, NB 08) |
| `ollama` | Local LLM interface (NB 08, 09) |
| `fastapi`, `uvicorn` | API server (NB 10) |
| `dependency-injector` | DI container + service wiring (bonus) |
| `pydantic` | Request/response validation |
| `joblib`, `lightgbm` | Exported scoring model artifact |

Notes:
- Rule score boosting is intentionally disabled. The rule engine is used for explainability, prioritization, conflict resolution, and analyst decision support.
- Synthetic fraud augmentation was explored but not used in the final training set because no reliable synthetic fraud rows were added.
- The RAG and multi-agent modules are lightweight local prototypes designed to demonstrate fraud reasoning and orchestration.
